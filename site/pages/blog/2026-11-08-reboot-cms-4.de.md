Reboot CMS begann als Markdown-CMS mit Blöcken. Eine Seite war eine Textdatei, und HTML-Kommentare teilten sie in Blöcke, die Templates ausgaben. Das funktioniert weiterhin. Version 4 bringt einen zweiten Weg, eine Seite zu bauen, und der wird zum Standard. Eine Seite aus Blöcken, die Formulare sind.

## Seiten aus Formular-Blöcken

Eine strukturierte Seite ist eine kurze YAML-Datei, `site/pages/about.yml` für die Adresse `/about`. Sie enthält einen Titel, eine Beschreibung und eine Liste von Blöcken. Jeder Block hat einen Typ und die Werte seiner Felder, eine Überschrift, einen Text, ein Bild oder eine Liste von Features.

Ein Blocktyp ist ein Ordner in `site/blocks/` mit zwei Dateien. Der Blueprint benennt die Felder, das PHP-Template setzt sie ins HTML. Der Admin baut aus dem Blueprint das Formular, ein Panel pro Block, und zeigt daneben eine Live-Vorschau, die dem gerade bearbeiteten Feld folgt. Die Redaktion füllt Inhalte aus, und das Layout bleibt, wie das Design es gemacht hat.

## Daten getrennt von den Seiten

Manche Inhalte sind gar keine Seiten. Seminare, Teammitglieder und Produkte sind Datensätze mit immer wieder denselben Feldern. In Reboot CMS 4 liegen sie in `site/data/`, eine YAML-Datei pro Eintrag, beschrieben von einem Blueprint in `site/blueprints/`. Der Admin hat einen neuen Bereich *Data*, der sie als Tabelle listet und als Formular bearbeitet.

Blöcke fragen die Einträge ab. Die Startseite dieser Demo zeigt die nächsten drei [Seminare](seminars), und ein vergangenes Seminar fällt von selbst heraus. Ändere einen Preis unter *Data*, und jede Seite, die das Seminar zeigt, ist auf dem neuesten Stand.

## Einträge, die Seiten sind

Mit `url: seminars` im Blueprint wird jeder Eintrag einer Collection zu einer Seite unter `/seminars/<slug>`, gerendert von einem Template neben dem Blueprint. Die [Seminare](seminars) dieser Demo funktionieren so.

## Markdown funktioniert weiter

An einer bestehenden Site muss sich nichts ändern. Markdown-Seiten, ihre Blöcke und ihr Frontmatter funktionieren wie bisher, und der Admin legt sie auf Wunsch weiterhin an. Ein Markdown-Block kann sogar in einer strukturierten Seite stehen. Ist eine Site bereit für Formulare, wandelt der Admin eine Markdown-Seite unter derselben Adresse in eine strukturierte Seite um, und die alte Datei bleibt in der Historie.

## Kleinere Dinge

Jedes Speichern einer Seite bewahrt die vorherige Version in der Historie auf, auch bei strukturierten Seiten. AddOns sind jetzt Ordner, mit eigenen Helfern und Admin-Seiten. Ein neues AddOn färbt die Codeblöcke einer Seite auf dem Server ein, zum Beispiel den hier:

```bash
git clone https://github.com/shaack/reboot-cms.git my-site
cd my-site
./run.sh
```

Reboot CMS 4 ist ein Major-Update, ein normales Update von Version 3 installiert es also nicht. Ab Version 3.23 bietet die Seite *Update* im Admin das Upgrade mit einem Knopf an, legt vorher ein Backup an und hält den Weg zurück offen. Der [Upgrade-Guide](https://github.com/shaack/reboot-cms/blob/distrib-4/docs/upgrade-to-4.md) beschreibt, was sich ändert. Version 3 bekommt weiterhin Sicherheitsupdates, es gibt also keine Eile.
